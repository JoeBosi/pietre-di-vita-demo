7. I documenti fuori dalla catena

Obiettivo: Capire perché sulla catena va solo l'impronta del documento e come ricalcolarla per controllare.

Il notaio non conserva nel registro il tuo contratto di 40 pagine: ci scrive il numero, la data e un sigillo. Se qualcuno cambia il contratto, il sigillo non corrisponde più.

Perché non mettere il PDF sulla catena

Scrivere sulla catena costa e ogni dato resta per sempre visibile a tutti. Un PDF o una foto sono pesanti, e possono contenere informazioni che non vogliamo rendere pubbliche. Sulla catena mettiamo allora solo l'impronta, 32 byte (tipo bytes32), mentre il file sta sul server del progetto (il backend).

Come si calcola

import { createHash } from "node:crypto";
import { readFileSync } from "node:fs";

// 1. The file stays on the server: here we read it as a sequence of bytes.
const bytes = readFileSync("report.txt");

// 2. The SHA-256 fingerprint is 32 bytes: we write it as 64 hexadecimal characters.
const fingerprint = "0x" + createHash("sha256").update(bytes).digest("hex");

console.log(fingerprint); // this bytes32 value goes into the contract as docHash

Per provarlo crea un file di prova e salva lo script qui sopra con il nome fingerprint.mjs (l'estensione .mjs permette a Node di usare import); la funzione documentIsIntact qui sotto va nello stesso file. Lo stesso script, già completo, è nella cartella starter/scripts/fingerprint.mjs del repository.

echo "Lab report, invented data, acidity 0.2" > report.txt
node fingerprint.mjs
0x5c94f9833f90635d7e6979852642be73376ee15c5502d6856961c1d35270d1b6

Riga per riga

  1. Le prime due righe prendono due strumenti già inclusi in Node.js: uno per l'impronta, uno per leggere i file.
  2. readFileSync legge il file (qui un file di testo, nella demo un PDF) e lo trasforma in byte.
  3. createHash("sha256") prepara il calcolo, update gli dà i byte, digest("hex") restituisce il risultato in lettere e numeri.
  4. Davanti mettiamo 0x perché così il contratto riconosce un valore bytes32.

La stessa funzione serve alla verifica: chiunque scarichi il documento può rifare il calcolo.

// Recheck: the fingerprint of the downloaded file must equal the one on the chain.
function documentIsIntact(fileBytes, hashOnChain) {
  const now = "0x" + createHash("sha256").update(fileBytes).digest("hex");
  return now === hashOnChain.toLowerCase();
}

Riga per riga

  1. La funzione riceve i byte del file scaricato e l'impronta letta sulla catena.
  2. Ricalcola l'impronta con lo stesso metodo.
  3. Restituisce vero solo se le due coincidono; con toLowerCase() ignoriamo le differenze tra maiuscole e minuscole.

Nella demo il backend calcola l'impronta all'arrivo del file (massimo 5 MB, solo PDF, JPG o PNG), la salva nel suo archivio e la scrive sulla catena come docHash. Alla verifica la pagina pubblica confronta le due impronte per ogni documento.

Un dettaglio utile: l'impronta prova che il file non è cambiato dopo la registrazione, non che il contenuto fosse vero.

Prova tu

Cambia il contenuto di report.txt (per esempio acidity 0.9), calcolane l'impronta con lo script qui sopra, poi cambia una lettera nel file e ricalcola. Confronta le due impronte con la funzione documentIsIntact.

Cosa hai imparato

  • Sulla catena si scrive solo l'impronta di 32 byte, non il file.
  • Il file sta sul backend e chiunque può ricalcolarne l'impronta.
  • L'impronta prova che il file non è cambiato, non che sia vero.
